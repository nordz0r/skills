## Основы

1. **AmneziaWG vs WireGuard.** Форк WireGuard с той же криптографией Noise; меняется только внешний вид: заголовки, паддинг, junk/сигнатурные пакеты. Ванильный WG узнаётся по типу сообщения 1–4 и размерам 148/92 байта. ✅ README amneziawg-go, `device/constants.go`.
2. **Версии 1.0 / 1.5 / 2.0 / 3.0 / 3.1.** Таблица — `awg-protocol.md`. ✏️ Сайт писал, что в 1.5 I1–I5 «работают только на клиенте»; по README их можно задать на любой стороне, просто рекомендуют на клиенте.
3. **Что совпадает на сервере и клиенте.** H1–H4, S1–S4, HeaderProtectionKey, RandomTrailers — обязаны; Jc/Jmin/Jmax, I1–I5, ContentPaddingAddition, таймеры, DisableCookies — нет. ✅ `receive.go` (`DeterminePacketTypeAndPadding`), README. Таблица — `awg-protocol.md`.
4. **Генерирует ли генератор ключи?** Нет: только параметры обфускации; `PrivateKey/PublicKey/PresharedKey` делает `awg genkey/pubkey/genpsk` на устройстве. 🛠 (правило «вырезай ключи из публикаций» — общее).
5. **Офлайн-режим, симулятор, массовая генерация, история (localStorage), источник случайности (`crypto.getRandomValues`), отсутствие бэкенда.** 🛠 свойства сайта, к протоколу не относятся; проверяется DevTools → Network.
6. **Где спрашивать.** Приложение/протокол — официальные репо `amnezia-vpn/*` (issues) и Telegram-сообщество Amnezia; по генератору — его репозиторий `Vadim-Khristenko/Any-Tech-ARCHITECT`. 🛠
7. **Два движка (AWG / Xray) — что выбрать.** Ставь то, что уже стоит на сервере. Выбор протокола — `vpn-setup.md`.

## Ключи и форматы

8. **`vpn://`.** Не шифрование: `qCompress` (4 байта длины big-endian + zlib) JSON → base64url. Внутри `containers[]`, `defaultContainer`, `hostName`, `dns1/dns2`, `description`; контейнер на протокол. ✅ `amnezia-client` (`exportController.cpp`, `apiUtils.cpp`: `qCompress` + `Base64UrlEncoding`). Ключи сервиса (Amnezia Premium/API) — подписочные, туннель внутри не лежит. ❔ формат подписи не разбирался.
9. **`vless://`.** Стандарт — XTLS/Xray-core discussion #716: `vless://UUID@host:port?type=…&security=…&sni=…&pbk=…&sid=…&fp=…&flow=…#name`; IPv6 в `[]`; для ML-DSA — `pqv`, для FinalMask — `fm`. ✅ release notes v25.7.26, v26.3.27. Пример — `xray-server.md`.
10. **`vpn://` vs `vless://`.** `vless://` — одно подключение; `vpn://` — набор контейнеров Amnezia, и `xray`-контейнер внутри по сути несёт те же поля. ✅ (по структуре JSON).
11. **Что секретно.** `PrivateKey`, `PresharedKey`, `HeaderProtectionKey`; в `vless://` — UUID. `pbk`/`password` — публичный. base64/zlib ничего не скрывают. ✅
12. **Слияние ключей (MergeKeys).** Склеивает `containers[]`; при одинаковых именах берётся первый. 🛠; что клиент Amnezia при дублях берёт первый — ❔ не сверено.
13. **Поменять обфускацию в готовом ключе без сервера.** Можно только sender-параметры (Jc/Jmin/Jmax, I1–I5, ContentPaddingAddition); H/S/HPK/ключи — только синхронно с сервером. ✅ по `receive.go`/README.

## Xray и REALITY

14. **REALITY vs AWG.** AWG меняет форму своих UDP-пакетов; REALITY проксирует настоящее TLS-рукопожатие донора и перехватывает соединение, только узнав клиента по ключу; активное зондирование видит донора. ✅ XTLS/REALITY README. От блокировки по IP не спасает ни то, ни другое.
15. **`target` и `serverNames` — один сайт.** Имена должны обслуживаться сертификатом target (тот же домен/SAN). ✅ docs `reality.md`. ✏️ поле теперь `target`, `dest` — алиас (v24.10.31).
16. **Выбор донора.** Официально: зарубежный, TLSv1.3 + H2, без редиректа; плюсы — близкий IP, шифрование после Server Hello, OCSP stapling. ✅ REALITY README. ✏️ «гигантов вроде microsoft.com не брать» — у сайта мнение; у ядра есть явное предупреждение для `apple/icloud/microsoft` и `.ru/.ir/.cn` — `xray-server.md`. География/популярность — ❔ эвристика.
17. **Ключевая пара, shortIds, spiderX.** x25519: приватный на сервере, публичный → `pbk`/`password`; `shortIds` — hex чётной длины ≤16, `""` разрешает пустой sid; `spiderX` — путь для краулера. ✅ `transport_security.go`, docs.
18. **`flow` / Vision / `-udp443`.** Единственное значение `xtls-rprx-vision`; суффикс `-udp443` — только клиент (разрешает UDP/443). Vision только поверх TLS/REALITY напрямую. ✅ `proxy/vless/*`, `infra/conf/vless.go`.
19. **XHTTP и режимы.** ✅ `dialer.go`, `transport_method.go`. Подробно — `xray-xhttp-finalmask.md`.
20. **`fp` (uTLS fingerprint).** Клиент имитирует ClientHello браузера (`chrome`, `firefox`, `safari`, `edge`, …); `unsafe`/`hellogolang` REALITY отклоняет. ✅ `transport_security.go`. «Отпечатки собраны измерениями» — 🛠.
21. **FinalMask.** ✅ `transport_finalmask.go`; список масок — `xray-xhttp-finalmask.md`.
22. **Почему параметры зависят от версии ядра.** Xray парсит JSON без `DisallowUnknownFields` — незнакомое поле молча игнорируется. ✅ (в `infra/conf` не используется). Таблица версий — `xray-versions.md`. ✏️ ряд версий на сайте был неверен (ML-DSA, VLESS Encryption, Hysteria, FinalMask, `minClientVer`) — исправлено там.

## Параметры AWG

23. **Jc/Jmin/Jmax.** ✏️ сайт: «Jc 3–7 обычно достаточно»; README: **4–12**; дефолт Amnezia — 3/10/30. `awg-protocol.md`.
24. **S1–S4 и совпадения длин.** ✅ размеры 148/92/64 (`constants.go`); запрещённые пары — `S2 = S1+56`, `S3 = S1+84`, `S3 = S2+28` (вывод). ✏️ «S4 ≤ 32 байт» (в исходнике сайта ссылка на `amneziawg-tools src/config.c`) — в tools v3.1.20260812, go и kmod такого предела нет; потолки S1 1132/S2 1188 в исходнике сайта обоснованы неверной арифметикой (65535−148 ≠ 1132) — не использовать.
25. **H1–H4, непересечение.** ✅ `headers must not overlap` (`uapi.go`).
26. **I1–I5 и теги.** ✅ README + `device/obf.go` + kmod `junk.c`. Таблица тегов — `awg-protocol.md`.
27. **`<d>/<ds>/<dz>`.** Есть только в amneziawg-go, в README не описаны. ❔ утверждение «в 3.0.1 вызываются с пустой нагрузкой, задел под AWG 4.0 (ветка feature/awg4)» не проверялось — не используй эти теги в переносимых конфигах.
28. **`<c>` — проблемный.** Только в модуле ядра; незнакомый тег ломает всю цепочку. ✅ `junk.c`, `obf.go`.
29. **Что дала 2.0.** S3/S4 и H-диапазоны (значение на каждый пакет). ✅ README.
30. **2.0 или 3.x.** 2.0 — самая совместимая; 3.x требует 3.x на обеих сторонах (мин. версии — `awg-protocol.md`). ✅ release notes клиентов. Остальное — оценка.
31. **Ширина H в 2.0/3.1.** ✅ по `receive.go`: при `RandomTrailers` длина больше не отсекает, и транспортный пакет сначала примеряется к H1/H2/H3 — доля ложных срабатываний ≈ (W1+W2+W3)/2³². Поэтому на 3.1 H1–H3 держи узкими. Точные числа сайта (CPU, «до 100M», «~20k») — ❔.

## AWG 3.0 / 3.1

32. **HeaderProtectionKey.** ✅ README (32-байтный ключ, `awg genkey`, nonce из паддинга). Что handshake/cookie шифруются целиком, а у транспорта — только заголовок — ❔ (по разбору сайта, в README нет).
33. **В Amnezia VPN ключ не виден.** Ключ генерирует приложение при включении опции в настройках протокола сервера. ❔ по UI; в `protocolConstants.h` ключа-дефолта нет.
34. **S ≥ 12 при HPK.** ✅ go `S%d must be more then %d to use headerProtection`, kmod `-EINVAL`.
35. **Таймеры.** WireGuard: 120/5/180 с, keepalive 10 с. ✅ `constants.go`. Условие `RejectAfterTime > RekeyAfterTime` — вывод; дефолты Amnezia — `awg-protocol.md`.
36. **ContentPaddingAddition.** WG выравнивает данные до 16 байт; добавка размывает сетку. ✅ README (тип/диапазон); описание эффекта — вывод.
37. **H1–H4 на 3.x всё ещё нужны.** ✅ `receive.go` сверяет H на каждом пакете при любых флагах.
38. **RandomTrailers / DisableCookies.** ✅ код go/kmod/tools; ✏️ хвост — случайной длины до «окна» пира, а не «до самого большого пакета». Детали — `awg-protocol.md`.
39. **«Уменьшить разброс H», «Отключить H1–H4», «Объединить S1–S4», «переключатели при смене версии», «режим роутера», «экстремальные максимумы».** 🛠 функции генератора. По сути: H=1..4 под HPK — ✅ это дефолты `amnezia-client`; одинаковые S — дефолт Amnezia (12); экстремальные Jc — README не запрещает (uint16), но замедляют старт.
40. **MTU 1280 в 3.1.** ✏️ не правило протокола: 1280 — дефолт мобильных клиентов Amnezia, десктоп 1376, `awg-quick` — MTU маршрута − 80. `awg-protocol.md`.
41. **RandomTrailers обязан совпадать.** ✅ `receive.go:618`.
42. **Кто поддерживает 3.0.** ✅ go/kmod/tools 3.0+; клиенты — `awg-protocol.md`.

## Клиенты

43. **Клиент ≠ движок.** Официальные приложения Amnezia (Android/iOS/Windows/Amnezia VPN) работают на amneziawg-go, OpenWrt и Linux-сервер — на модуле ядра; набор тегов и пределы определяет движок. ✅ README платформ amneziawg-go; движки сторонних клиентов — ❔.
44. **WireSock не шлёт I1–I5.** ❔ закрытый продукт; по сайту — release notes WireSock 3.4.4.1/3.4.5.1. Проверяй у вендора.
45. **Какой клиент лучше.** Официальные клиенты Amnezia первыми получают новые версии протокола. ✅ release notes.
46. **Матрица клиентов (mihomo `version: 3`, OPNsense Jc 1–128, Keenetic, ASUS Merlin, WG Tunnel).** ❔ сторонние, не сверялись.
47. **Почему параметры зависят от клиента.** Windows < 2.0.2 не сохранял H > 2147483647. ✅ release notes amneziawg-windows-client 2.0.2 («fix h values highlight»). Теги — движок (п. 26).
48. **wg-easy принимает H только 5…2147483647.** ❔ сторонний проект, не сверено.
49. **Установщик `awg-containers-and-tools`.** ❔ сторонний; разбор и security-ревью — `third-party-tools.md`; официальные пути — приложение Amnezia (`docker-stack.md`) или `awg-quick` (`linux-awg.md`).
50. **Поля экрана AWG в Amnezia VPN.** Соответствуют ключам конфига: подсеть/порт, Jc/Jmin/Jmax, S, H (диапазоны), I1–I5, HPK, ContentPaddingAddition, 5 таймеров, RandomTrailers/DisableCookies. ✅ `protocolConstants.h`.
51. **Параметры на каждое устройство.** Shared — общие на сервер; sender-параметры можно и полезно разнообразить по устройствам. ✅ README (client-side).

## Предупреждения и проблемы

55. **Когда обфускация бессильна.** Блок по IP/ASN или белые списки. ✅ (следует из устройства протоколов).
56. **Анонимность.** Обфускация её не даёт: виден IP сервера, объёмы, время. ✅
57. **Не поднимается.** Сначала shared-параметры и версия; затем порт/firewall. ✅ `vpn-setup.md`.
58. **`Invalid argument`.** S<12 при HPK, пересечение H, ключи чужой версии. ✅ `uapi.go`, `netlink.c`.
59. **`Message too long`.** ✅ механизм (`-EMSGSIZE` в `netlink.c`); ✏️ цифры «3,4 КБ/3200 байт/3820 байт» — ❔ не измерены.
60. **Долгое подключение.** Меньше Jc/Jmax и I-пакетов. ✅ README (отправляются перед каждым handshake).
61. **Работало и перестало.** Таймеры (3.x) или блок сигнатуры; кнопка «Не работает» — 🛠.
62. **Сменил параметры на сервере — всё отвалилось.** Согласования нет: сначала раздай новые конфиги, потом меняй сервер (или второй сервер). ✅ (shared-параметры).
63. **Насколько замедляет.** Разово — Jc×средний размер + I-пакеты; постоянно — S4 и ContentPaddingAddition съедают MTU. ✅ вывод из README.
